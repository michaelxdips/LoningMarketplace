### Initial-route interpretation

The homepage `App` is statically imported into the main chunk. Product, UMKM, editorial, login, and management routes are lazy chunks. Ignoring network framing, cache headers, and images, the homepage's build assets are therefore approximately:

```text
HTML shell 1.35 kB + global CSS 53.56 kB + main JS 502.08 kB
= 556.99 kB minified
= 164.96 kB gzip (0.48 + 9.72 + 154.76)
```

This is an asset-transfer approximation, not Lighthouse, Core Web Vitals, parse/execute time, or a network waterfall. Images and API JSON are not included. A detail route adds its lazy route chunk and shared imports according to the browser/module cache.

## Request and query cost baseline

Source-derived bounds:

| Flow | Frontend HTTP requests | Repository database queries | Notes |
|---|---:|---:|---|
| Cold homepage, no filters | 2 logical catalog GETs | 2 | one product list and one UMKM list; each is one joined query |
| Settled homepage search/category | 2 filtered logical GETs, plus cold unfiltered queries that remain enabled | 2 per request pair | 300 ms debounce; React Query caches each key for three minutes |
| UMKM detail | 2 | 2 | UMKM detail, then products by `umkmId` |
| Product detail, current UI | 2 | 2 | product detail, then parent UMKM; no related request is currently wired |
| Related endpoint when called directly | 1 | 2 | current-item lookup plus one joined bounded candidate query |

These are source-level query counts. They do not include retries, browser cache, proxy behavior, analytics `POST /api/events`, or concurrent users. API retries are limited to one retry only for network/5xx failures. The homepage hooks intentionally do not use `AbortSignal`, so previously started requests are not cancelled when keys change.

No N+1 loop was found in public list or related-result mapping. This does not substitute for a PostgreSQL query plan or production trace.

## Search scalability baseline

- Search uses escaped `ILIKE '%query%'` across multiple product/UMKM text fields.
- Returned rows are bounded to 100; related rows are bounded to four.
- The schema has category, status, order, parent, and slug indexes, but no trigram search index.
- The leading wildcard creates a scan-cost ceiling that the result limit alone does not remove.
- No production table cardinality, `EXPLAIN (ANALYZE, BUFFERS)`, p50/p95 latency, DB CPU, or concurrency measurement was available. No numeric capacity claim is made.
- Trigger a `pg_trgm` investigation when representative measurements exceed the agreed search-latency/DB-CPU budget or show sustained broad scans. Any extension/index change requires a separately reviewed migration; none was created here.
